ICURLHTTP HANDOFF -- Tool-Submit 1.0

Do not send any request while following the offline demonstration.
Do not put your token in the form, C code, snapshot, README, or chat.

For the real requests generated by the program:

URL:
https://api.github.com/graphql

METHOD:
POST

CUSTOM HEADERS (one per line; enter the real token only inside iCurlHTTP):
Content-Type: application/json
Accept: application/json
Authorization: Bearer YOUR_PRIVATE_TOKEN
User-Agent: Shakti-Submit-1.0

POST DATA / REQUEST BODY:
Paste the complete contents of the numbered request .txt file.
These files contain JSON, although their extension is .txt for the phone.
Do not paste this instruction sheet or the console's BEGIN/END markers.

SECURITY:
Keep Insecure Mode OFF. Do not bypass a TLS/certificate failure.
Keep redirects disabled where the app offers that setting.
Use a repository-scoped credential with only the permissions needed.
For creation of a branch and a commit, repository Contents write access
is ordinarily needed, subject to organization and repository policies.
Use read-only access for the check when practical. No elevated scope is
required by this program merely to prepare local files.

The iCurlHTTP source documents saved header and POST-data history.
Treat that history, diagnostic output, screenshots and clipboard as sensitive.
Never share a screenshot or diagnostic record containing Authorization.

RETURNING A RESPONSE:
Copy only the JSON response BODY, from its opening { to its closing }.
Save it under the exact response filename printed by the C program.
Do not include HTTP headers, transfer timings, request text, or log prefixes.
An HTTP success code alone does not prove the GraphQL operation succeeded:
GraphQL may return an errors field. The checker rejects such a response.

STEPS FOR BATCH example_001:
example_001.01-check.txt     read-only query
  -> example_001.01-response.txt
example_001.02-branch.txt    creates a NEW review branch only
  -> example_001.02-response.txt
example_001.03-upload.txt    commits the approved new/changed files together
  -> example_001.03-response.txt
example_001.04-readback.txt  reads the resulting commit and selected text files
  -> example_001.04-response.txt

The program itself never sends HTTP and never reads the token.
The original base branch is not an upload target. No merge is generated.
Do not blindly resend a mutation after a network timeout: it may already
have succeeded. Inspect the actual GitHub branch/commit before proceeding.
A failed commit can leave the new review branch present without the upload.
No automatic rollback or deletion is attempted.
