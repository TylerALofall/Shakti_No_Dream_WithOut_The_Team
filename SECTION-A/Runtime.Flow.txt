SHAKTI RUNTIME FLOW — 2026-10-18

This change implements the C loop behind the agreed flow. It does not supply
a Swift application, a media codec, speaker playback, or a trained ML model.

BUILD FROM THE REPOSITORY ROOT
cc -std=c99 -pedantic -Wall -Wextra -Werror -O2 -Iinclude SECTION-A/*.c -o shakti-runtime

The console host uses POSIX nonblocking input and monotonic pacing. The
controller-facing API is include/shakti_app.h. One owner serializes calls;
initialize once with the existing Eden/control/manifest data. Do not call
cycle or reuse leased buffers concurrently from different threads.

FOREVER LOOP
A quiet shakti_app_cycle(runtime, NULL) needs neither input nor a reply.
The console runs forever by default, including after stdin EOF. /quit/ and
/interrupt/ hold MCP tools; they do not stop heartbeat, recall or reasoning.
The native controller must keep scheduling cycles while its tool gate is held.
--cycles N is an explicit bounded local RUN, never the default lifetime.

CLOCK AND HEARTBEAT
Resting rate is one beat per second. Each logical beat contains 64 hearing
slots and 32 sight slots. /heartbeat/ accepts 1, 2, 4, 8, 16, 32 or 64 beats
per physical second. Every channel follows the same rate; 2:1 is retained.
Integer remainder pacing avoids accumulated rounding loss.

The clock seeds once from the host epoch, then advances one logical second
per beat. The frame suffix is an event ordinal, not a camera frame number.
Startup checks existing epoch records and resumes beyond the latest stored
epoch. Explicit --epoch N is for repeatable local RUNs and refuses a backward
origin on an existing recording. Cycle counters and rate restart at their
initial values; recorded epochs and actual tool counts survive restart.

shakti_loop_heartbeat_audio() exposes a mono signed 16-bit PCM frame at
48,000 samples/second. Consume exactly its returned sample count after each
cycle. Sample counts scale with rate so a faster beat does not build a PCM
backlog. The first slot carries a pulse. The native audio adapter must play
these frames; this C source does not open a speaker.

LOADING, TAKING, AND VALIDATING
The Swift/native decoder deposits full decoded RGB/RGBA pixels or PCM clips
through shakti_app_queue_frame(), which records the accepted deposit.
A queue refusal transfers no ownership and changes no caller bytes.
Four complete-source-window descriptors can wait in the loading zone.

A movie window requires:
  lane 0: full sight frame at even position64
  lane 1: first audio microclip at that same position64
  lane 2: second microclip at position64 + 1

position64 is the source timeline measured in 1/64 of a source second.
A picture/rendered document page uses mask 1. A sound-only pair uses mask 6.
A movie uses mask 7. Pair by source_id and position64 / 2, never by arrival
time. At sample rates such as 44,100 Hz, clip lengths retain the fractional
sample boundary; no source samples are silently discarded.

Queueing borrows input bytes unchanged until the item is taken. Keep all
caller-owned storage alive and disjoint until release or explicit cancel.
Taking immediately copies every lane into independent reference and
processing buffers. The processing copy is broken into eight binary bit
planes for byte-exact rebuilding. These are bit planes, not an 8x8 image.
There is no spatial reduction, thresholding or color quantization.
RGB/RGBA sample values and channel bits are retained, including alpha.
Every rebuilt output byte starts different from its expected reference byte.
Skipping reconstruction or writing only part of the output cannot pass.

Sight and first audio are checked on an even slot, second audio on the next
odd slot. Each reconstructed byte must match the held reference, and any
supplied expected hash must also match. Incomplete or bad windows cannot
enter the current sensory view. A bad window stays held for explicit cancel
or recovery while the rest of the loop continues.

The oldest incomplete window applies backpressure to later windows. A
validated current view leases its buffers until shakti_media_release().
Do not recycle those buffers earlier. This bounded queue does not silently
drop or resize frames when the native producer is faster than consumption.

CONVERGENCE AND STATIC MEMORY — REVISED 2026-10-18
shakti_app_convergence_view() exposes only actual rebuilt sensory pointers,
resident Eden, whole working and short-term capsules, pending review count,
native retained-media descriptors and the current thought. Input/reference/
binary-work pointers are not in the sensory view. Eyes and mind borrow the
SAME rebuilt C buffers. This is in-process shared memory, not a supplied IPC
mapping. Consume only after a successful cycle and before buffer release.

All program-owned pools and buffers have fixed capacities, with no explicit
heap allocation. New semantic capsules enter working memory, not the library.
/working_memory/ accepts 20 through 90 HER logical heartbeat seconds; the
implementation default is 60. Repeated activation does not extend an existing
working lease. A whole item demotes into short term when that lease ends.
Admission reserves a future short-term slot: 64 unique resident capsules
across the two fixed 64-slot arrays. Full unfinished pools hold new admission.

Unused recent short-term capsules fade after /memory_decay/ positive BEATS.
The implementation default is 600 heartbeat seconds; Tyler has not selected
the final short-term decay rate. No capsule can fade or enter the library
before FIVE DISTINCT complete thirteen-answer self-reflections link to its
exact id. Unfinished reviews remain pending. Training capsules, once reviewed,
remain resident without recent-event decay. Eden stays resident separately.

Long term is an append-only SMC2 capsule file, memory_capsules_v2.bin. Each
record begins with its commit epoch and preserves origin epoch/frame, immutable
id, tags, chosen logical method/location, optional exact media source/range,
all five answered question sets, checksums and a DONE footer. No raw movie or
PCM is written into the library. Later recall brings a complete capsule back
to RAM and current convergence. A checksum detects accidental corruption;
it is not a cryptographic seal or proof of semantic correctness.

The separate memory_pending_v2.bin checkpoint preserves working/short stages,
timing, organization and review identities. Complete reflection receipts have
their own recovery/audit file. File writes flush and fsync; checkpoints replace
atomically after a complete write. Startup validates the whole snapshot before
admission. An incomplete/corrupt record holds work rather than publishing a
fragment. Native process-restart recovery was exercised; power-loss behavior
and device filesystems have not been qualified.

Legacy memory_containers.bin is preserved untouched. Its immediate-admission
SMC1 items are not silently labeled five-reflection SMC2 memories. Historical
reflection control state can restore from actual answer logs. Legacy capsule
migration/curation is not implemented by this patch.

Base semantic content is limited to 16,383 bytes. A reviewed whole capsule has
65,535 bytes including all question/answer sets. Tags allow 255 bytes, ids 63,
method 255 and logical location 511. Limits refuse whole over-capacity items.
Method/location describe her organization within the native store; they do
not create arbitrary per-capsule directories. Native cold-id scans and startup
audits are synchronous. The host is not a hard real-time implementation.

MCP memory actions:
  recall trigger words
  remember id | tags | recent|training | complete semantic text
  activate id
  organize id | method | logical location
  reference id | source_id | first position64 | last position64
  release_artifact capsule_id

The command line remains limited to 1,023 bytes. Native memory_store() accepts
the full base-content bound. Reference a source before the first reflection.
Generic logs and per-frame validation metadata are audit events, not automatic
library admissions. Actual reasoning chooses the semantic capsules to retain.

NATIVE MOVIE ARENA
shakti_retention.c reserves exactly 512 MiB in a static C arena: 448 MiB for
history, 32 MiB for the latest window, 32 MiB for encoding/recovery work. Fixed
descriptors and an additional 8 MiB transcript buffer are outside that arena,
so the total program reservation exceeds 512 MiB. No outside process owns it.

Only already validated rebuilt bytes enter this short-term arena. Lossless
pixel/sample runs compress solid colors and repetition; other content uses a
raw fallback. There is no spatial size reduction. Every source frame still
passes the full binary/rebuild/validation cycle before retention sampling.

Retained visual cadence becomes at least every other frame after 20 source
minutes and every fourth after 40. Byte/descriptor pressure can double the
stride further, uniformly across history. The FIRST and a separate LATEST
full window remain available together. Actual byte costs, not assumed video
compression ratios, drive this decision. Raw 1920x1080 RGB at 32 fps is 189.84375 MiB/s;
512 MiB is only about 2.7 seconds raw. Half/quarter alone cannot fit long movies.

Untranscribed PCM is pinned even when its associated image is thinned. Native
shakti_app_transcribe() accepts actual model-produced text with its source
range and epoch receipt; empty text means confirmed silence. Text segments
survive video thinning. If pinned data fills the budget, new intake waits;
heartbeat and reasoning continue. This patch does NOT supply an ASR model.

Exact repeated payloads can share a retained range. Learning that different
pictures represent the same car, reusing shapes/colors, and retaining rare
instance features requires the real native reasoning/ML adapter. It is not
implemented by an XML label, a fixed category table, or an exposure counter.

One active source owns the arena until consolidated. Other sources wait in
the loading zone. release_artifact requires no leased/queued frames, completed
transcription, and an archived five-review capsule whose source id and range
cover the whole active artifact. The library capsule remains after raw media
is released. This bounds storage by applying backpressure, not deleting the
beginning of an unfinished movie.

A checksum-protected native short-term journal records every admitted window
and actual transcript. It compacts atomically to retained samples after its
size threshold, and rebuilds/validates saved payloads on restart. Temporary
old/new files can exceed the arena byte size; this is native file storage,
not long-term video admission. Complete encoded windows are limited to 32 MiB;
oversized windows are refused whole. An uncompressed 1080p RGB window fits.
Performance including per-window fsync has NOT been qualified on a phone.

REASONING AND REFLECTION
The existing Eden/evidence reasoner revisits the current focus on sight
slots, quietly. Changed thoughts are logged and stored as whole artifacts.
Repeated evaluation checks deterministic agreement; it does not prove
semantic correctness. The existing reasoner does not infer meaning from raw
pixels, PCM, or arbitrary episodic prose. Those inputs are available together
through the convergence view for the native reasoning/ML adapter.

After ten recognized dispatched MCP tool calls, another tool waits for
thirteen actual answers. Pending semantic capsules also request a real review
every 20 heartbeat seconds, so quiet periods can consolidate memory. Timed
reviews do not invent tool calls. Quiet cycles, messages and unknown names
do not count as dispatched calls. Handwriting trials are explicit continuations
of an already dispatched lesson.

shakti_loop_set_reflection_provider() registers compiled nonblocking
reasoning code. It receives one unanswered question per cycle. Return zero
when an answer is not ready; return one with a complete NUL-terminated actual
answer when ready. The default is NULL and leaves reflection pending.
There are no fixed production answers and no stdin prompt.

A native adapter can also use shakti_loop_answer_reflection(); the console
control is /reflection/answer/ 1..13 actual answer. This is a control route,
not another tool call. /reflection/ displays status without asking for input.
The gate opens only after all thirteen answers are stored together. Question
13 names exact pending capsule ids to consolidate. A reflection receipt id
counts once per linked capsule; four complete reflections cannot promote it.

Question 12 supplies trigger words for recall. Up to fifteen complete words
fit the bounded tag field; its full original answer stays in the reflection.
A pending recall is kept until the current lookup ends. All answers and
actual tool counts restore from checked epoch records after restart.
Multiline answer bytes are preserved. The reflection id identifies the tool
batch or timed review, so retrying after a committed audit receipt reuses
that whole receipt instead of creating another copy. Restart reconstructs
calls since completion by epoch ordering, including mixed timed/tool reviews.
Restoration uses the new actual_call and complete_13_answers records. Older
response-count reflection records are not reinterpreted as these tool batches.

SCOPE STILL OUTSIDE THIS CHANGE
The branch contains no Swift source/project to connect native decoding,
display, audio playback, lifecycle, and the compiled reasoning adapter.
The source window API and PCM output are ready for that integration.
No camera, video codec, speaker, phone, or trained model was exercised.

The Section-A handwriting font/receptor remains an 8x8 teaching surface.
The old SECTION-E eyes/font demonstration is separate and is not used by
the new full-size native media queue. It must not be used as full vision.

The prenatal programs in SECTION-B were not migrated or retrained here.
The requested 19-week sound, 25-week colors and 22,982,400 stateless beats
remain a separate training integration; this change does not claim them.
